# Track changes implementation plan

Scribe 0.20 includes the internal review infrastructure described here; Track Changes is not an exposed editor feature yet. Further DOCX review interoperability is being developed on `development/docx-review`. Earlier implementation notes below describe the progression of this work.

The current editor uses semantic paragraphs/runs projected into a shared AppKit text storage. Native character formatting goes through NSTextView, while styles, lists and structural operations also use document transactions. Comments already preserve associations through attributed metadata. Track changes must cover both editing paths and retain native undo, input methods and selection.

The first implementation adds versioned run review metadata and core decisions for insertions, deletions and character formatting. Pending deletions retain original rich runs. Authors have stable identities independently of display names. Formatting decisions replay field differences in order, so rejecting an old bold change does not discard a later font-size change or a later accepted decision. Accept/reject operations must also rebase comments and reconcile deleted note references atomically.

Remaining integration:

1. Extend the integrated paragraph-separator review paths to the remaining structural cases. Core accept/reject already joins paragraph chains, rebases comments/bookmarks, preserves inherited character appearance, and handles note paragraphs. Paragraph formatting now has a separate development history for style associations, geometry, lists and page-break-before. Decisions replay field differences without restoring text. Joining away a paragraph with unresolved formatting is refused until those decisions are resolved; accepting/rejecting all resolves the formatting first. Native transaction/projection regressions and the full paragraph-stage sanitizer/launch/Office run pass.
2. Project review metadata without confusing author formatting with revision decoration. Preserve metadata through native undo, recovery and clipboard; do not inherit another author's revision when typing.
3. Finish native integration. An internal, unexposed author session now tracks committed text insertion/deletion, rich replacements and character formatting through native undo. Grouped typing shares a revision identity. Marked-text composition now has native regressions for preview, commit/cancel, partial/external replacement ranges, stable autosave, undo and close cleanup. Physical input-method validation, broader paragraph formatting/document-transaction coverage (including style-definition review), remaining structured replacement and boundary-join cases, note-dialog tracking and object-property changes still need integration. Short text edits now validate a bounded fragment; structural and object edits still validate the complete candidate. A 256-page native benchmark verifies glyph coverage and reversibility. Further profiling with many revisions, notes, structural edits and physical input remains required before exposing the feature.
4. Expose Track Changes, previous/next, accept/reject current and all, with readable revision presentation and keyboard-accessible navigation. Test edits around pending deletions and accept/reject undo.
5. Implement actual Office XML insertion/deletion/format revision structures, author/date preservation and regression fixtures. Until supported, DOCX export of pending revisions must fail explicitly.
6. Validate native save/reopen/recovery, exported packages and screen/PDF output; profile large revision collections. Remove temporary editor gates only after native editing is safe.

Scribe 0.20 uses native format v14. Existing v13 documents migrate in memory, with no pending review metadata. The application currently refuses to open pending revisions while interaction support is incomplete; attributed projection is being tested separately for lossless preservation. No track-changes release or manual Word/accessibility validation is claimed.

The composition session preserves a stable pre-composition projection for autosave. Before undo/redo, the editor cancels provisional input using [UndoManager notifications](https://developer.apple.com/documentation/foundation/nsnotification/name-swift.struct/nsundomanagerwillundochange). Semantic document commands commit composition before mutating the model. These paths are covered by native tests; they do not replace physical CJK/dead-key/VoiceOver testing.

Paragraph history retains the existing full paragraph-format override semantics. Comparison defaults are captured with each edit so changing a style definition cannot retroactively change the fields represented by a revision. A style association without direct paragraph formatting continues inheriting the live style. A future partial paragraph-override model remains separate work; this implementation does not silently migrate old direct formatting.

Tracked list Return now has a semantic operation in development: selected original text remains a deletion; one's own draft selection is removed directly; a new separator is recorded; the old separator history moves to the continuation; comments follow semantic UTF-16 positions. Continuation paragraphs project shared formatting histories without duplicating first-item restart/page-break properties. Empty-item Return records list exit/outdent as paragraph formatting. Native Return, own-separator joins, repeated Forward Delete and Return–Backspace–Backspace regressions pass; cross-list replacements now use the semantic range transaction described below.

Deleting a single separator inserted by the active author now joins through the semantic model, removing generated list markers and rebasing annotations. The operation isolates that boundary from any shared insertion identity. Formatting newly drafted by that author on the continuation can disappear with the draft paragraph; older or other-author paragraph revisions remain protected by the join guard. Forward Delete after a retained separator moves past the next generated list marker to editable content. Multi-paragraph replacements now use the semantic range transaction described below.

Single-paragraph newline replacements are being routed through the semantic split operation for ordinary paragraphs as well as lists. This projects first-only page-break/restart properties onto the continuation, preserves rich selected deletions and keeps literal tabs distinct from generated list markers. Empty final paragraphs receive explicit semantic typing attributes. Core coverage and the native ordinary-paragraph cases pass; broad sanitizer/launch/Office validation follows.

Validated semantic structure commands now reuse their existing before/after models and can replace only changed ordinary paragraphs in native storage, preserving undo snapshots. Complex rendering contexts retain the full projection path. The 257-page Return benchmark still measures 0.39–0.97 seconds after this first optimization; bounded native structural edits and deferred/incremental layout remain required before public review editing is considered responsive.

Eligible ordinary Return now uses a bounded native paragraph projection and an explicit fragment/selection/typing-attribute undo command, with semantic fallback for complex contexts. Native regression coverage includes empty paragraph identities, caret undo/redo, unrecorded edits elsewhere, cross-page focus, trailing empty paragraphs and composition focus retention. Input calls on the long fixture now measure about 3–11 ms, but following reflow can still block for hundreds of milliseconds. The next performance task is budgeted asynchronous pagination while retaining synchronous exact layout for output and explicit navigation.


Ordinary-body reflow now continues across scheduled batches while preserving a synchronous complete-layout path for output/navigation. Note/table passes remain synchronous. TextKit's independent [idle-time background layout](https://developer.apple.com/documentation/AppKit/NSLayoutManager/backgroundLayoutEnabled) is disabled because the editor owns deferred scheduling. Native range comparisons and sampled rendered PDFs pass, but visible-window heartbeat measurements still expose main-thread stalls. Process sampling and mid-reflow deletion coverage are recorded in VALIDATION.md; bounded physical input latency remains unverified.


Process sampling also found work outside pagination: recovery recaptured the same document for outline refresh, and capture repeatedly converted identical fonts/colours. The recovery callback now reuses its snapshot, and character formatting conversions are cached within a single capture with a bounded number of entries. This cache does not include review or paragraph identities in its key; those are still captured independently. Styles, logical script fonts, requested missing faces and explicit highlight removal remain distinct.


Cross-paragraph inline replacements now use `DocumentCore.replaceTrackedRange`, preserving original retained deletions and joining selected own draft boundaries atomically. This prevents generated list numbers from becoming authored text when a change is rejected. Comments, bookmarks and rich incoming runs remain semantic data. Joining away unrelated paragraph-format review is intentionally refused until that history is resolved. Return and multiline typing/plain-text paste now build inserted paragraph fragments within the same semantic replacement transaction, including an emptied draft list item. New text and separators share one insertion identity; native Return, paragraph-mark formatting and own-list replacement undo/redo regressions pass. A 1,000-paragraph insertion can be rejected in one decision. Multiline rich paste now records copied paragraph properties with its insertion group; tracked table paste still requires a separate table transaction.


Compound rich paste now uses optional `RevisionIdentity.groupID` metadata within unreleased native v14. Kind-specific identities remain distinct, and grouped members must agree on author/date. Document-level accept/reject expands a component to its group. Copied paragraph properties have reversible formatting histories, so rejecting a paste restores original style inheritance, while accepting it preserves the copied styles independently of older review decisions. Older identities without `groupID` remain independent and decode unchanged.

Deleting an author's own grouped boundary isolates that boundary from the rest of the group. Pasted runs retain their appearance; original runs keep inheriting the surviving paragraph's history. Joining must not discard independent accepted or other-author formatting. Such joins are refused until the conflicting review context is resolved. Core regressions cover both deleting one boundary and replacing across it; native rich-paste and actual RTF clipboard tests verify grouping, alignment and undo. Native output artifacts are independently inspected by `scripts/verify-review-paste.py`.


`RevisionIndex` now exposes pending compound changes with stable group IDs, component IDs and semantic UTF-16 locations in body paragraphs and notes. Adjacent run extents coalesce without absorbing paragraph separators; accepted history is excluded. Navigation wraps in body order followed by note registry order and recovers from stale selection. Document-level decisions accept either a component or group ID. Validation prohibits group/component ID collisions. This is the data foundation for review navigation; the public panel and commands are still pending.

`ReviewLocationProjection` maps index locations to native body selections or semantic note ranges with their body reference. It selects separator characters without swallowing the following list marker and refuses stale paragraph/reference projections. Native body/note regressions pass. Connecting this mapping to public review commands remains a separate integration step.


The internal `ReviewNavigation` coordinator now commits marked input before building its index, selects native body/note locations, wraps previous/next navigation and advances to a surviving change after a decision. Accept/reject current and all use semantic document transactions with native undo. Stale selections cannot resolve a different change; closing windows refuse commands. Native controls remain unexposed while the broader editing integration and visual revision presentation are incomplete.


A native review sidebar now lists compound changes with author/date and changed-text details, previous/next, current accept/reject and an explicit all-change menu. It preserves keyboard focus after decisions, reloads through document undo and hides/restores with Focus Mode. Native selection/action tests and rendered panel inspection pass. The panel is instantiated but not exposed in public menus yet; visual revision markings and the remaining editing paths precede removing the development gates.


Revision drawing now extends the existing AppKit temporary-attribute delegate: insertions use green underlines, deletions red strikethroughs, and pending formatting a blue dotted underline. Decoding is cached within a bounded 256-entry/1 MiB cache per drawing owner. Only the requested attribute extent is inspected; document text and formatting are not mutated. Body and note flows share the helper, generated note labels are excluded, and Find backgrounds are retained. Ordinary printing excludes temporary marks; explicit marked-review output now includes them through the renderer. Paragraph break and paragraph-format markers are now drawn in the margin, including empty final paragraphs.


PDF export now offers Show tracked changes, Accept pending changes, and Reject pending changes when revisions exist. Printing offers the same choice before the native print dialog. Review output uses an isolated semantic copy with a fresh document/recovery identity; the source and its undo history are unchanged. Switching the PDF mode rebuilds the output layout and validates page ranges against its page count. Marked output includes body, footnote and endnote text marks; accepted/rejected output resolves a copy first. Pending native-open gates remain until all editing paths are safe.


Structural review marks use ¶+ for inserted breaks, ¶− for deleted breaks and ¶~ for paragraph formatting. The body, footnote and endnote renderers draw them separately from text, preserving glyph ranges and document content. Empty final paragraphs use their semantic history and the native extra-line fragment. Marked output preflights the required left margin and rejects clipping before writing; PDF-panel validation allows selecting resolved output instead. Very narrow screen margins still need adaptive marker placement.


Empty-note review navigation now maps collapsed semantic ranges to native caret lines, including the final extra line and note continuation pages. Review and Find clear each other's page presentation; returning to native body selection restores body-page status. The sidebar identifies empty-paragraph formatting explicitly. Visible-window regression coverage also exposed a document-close lifetime bug; closed window controllers now detach their document reference before the document can deallocate.

Tracked note dialogs now use a private `NoteReviewSession` with the existing native editing engine, a separate Undo manager and no independent recovery file. The compact draft uses linked TextKit containers; its editing-page geometry is temporary and does not change the note's actual placement in the parent document. Apply commits marked input and validates semantic note paragraphs; Cancel discards the draft. Parent-document Apply is undoable. Character insertion/formatting, long-draft flow and marked-input commit have native regression coverage. Editing a retained deleted note reference explicitly requires rejecting that deletion first. Tracking-disabled dialogs keep their existing rich editor; transitions involving existing revisions, broader object/paragraph operations and physical IME testing still require coverage before the public review gate can be removed.

Tracking-disabled notes with existing revisions now retain the same native engine and visible marks. New plain typing does not inherit earlier revision identities. Untracked character and paragraph formatting records accepted later history while older changes remain pending; rejecting the older change therefore preserves the newer formatting. The history compacts when decisions finish. Native Undo/Redo and note tests cover these transitions. Complex replacement/paragraph-boundary transitions, global style edits and object operations remain prerequisites for exposing the public tracking switch.

Tracked inline replacements now clamp selections inside generated list numbering to the semantic content start. Marker-only deletion is a no-op; formatting excludes the generated prefix; typed/pasted text equal to a marker character still becomes authored content. Cross-paragraph replacements retain their semantic transaction path. Initial marked input is similarly redirected before creating the composition snapshot, preserving numbering during preview and cancellation. The guard skips ordinary body text by attributes before any paragraph search. Untracked marker editing and broader tracking-disabled structural replacements remain separate work.

The shared list-marker guard now also protects ordinary typing, native marked input, formatting and single-paragraph deletion when tracking is off. Native Undo owns those untracked edits. The helper lives in Formatting because both input paths use it. Cross-paragraph ordinary list replacements still need their own semantic editing audit; the tracked path already uses the document transaction.

Ordinary cross-paragraph list replacements now use the same semantic transaction as tracked replacements, immediately resolving only the new operation's revisions. Existing pending decisions are retained. The resulting caret is rebased over resolved deletions; paragraph joins retain comment/bookmark handling and exact model Undo. This fixes Forward Delete turning the next generated number into authored text. Native typing and multiline replacement across list items pass, as do exported native/DOCX/PDF fixtures. Untracked marked input across an existing multi-paragraph selection remains an input-method integration case to audit.

Untracked marked input across list paragraphs now uses a stable composition snapshot too. Preview edits cannot enter autosave/recovery snapshots; committing restores the original projection before applying the semantic replacement. Initial endpoints inside generated numbering normalize to content boundaries, keeping partial markers out of the preview. Cancel and Undo during composition preserve the original document and native Undo grouping. Notes that still use the plain rich-text dialog rather than the embedded engine require separate structured-list coverage.

All note drafts now use `NoteEditingSession`, including initially plain notes. This avoids losing semantic list operations when rich paste introduces structure after the dialog opens. The wrapper delegates capture, Undo and close cleanup to that one engine; Apply explicitly commits both ordinary marked input and custom review composition. Existing modal Apply/Cancel, clipboard and review behavior remains covered. Wider imported objects and full sanitizer/launch validation remain release checks for this integration.
